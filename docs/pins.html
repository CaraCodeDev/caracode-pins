What it is

Pins is an integration for Astro's dev toolbar. It adds a Pins panel. Turn on pin mode, click anything on the page, and type what you want: "tighten this spacing", "make these titles bigger", "hero should take an image or a video".

It's built for two jobs:

  • A quick pass of tweaks. Pin a dozen small things in a couple of minutes, then hand the pile to Claude instead of describing each element in words.
  • Planning a CMS. Walk the page and pin what should be editable: "image or video, optional CTA with URL". Claude reads these as content notes rather than code changes, ready for the conversation about your CMS schema.

Pins only runs in astro dev. It never edits your source code, and nothing from it ends up in a production build.

Install

Needs Astro 7 or later and Node 22.12 or later. Run this in your site's folder. It installs the package and adds it to your Astro config.

bash
pnpm astro add @caracode/pins
bash
npx astro add @caracode/pins
bash
yarn astro add @caracode/pins
bash
bunx astro add @caracode/pins

Or by hand

bash
pnpm add -D @caracode/pins
bash
npm install -D @caracode/pins
bash
yarn add -D @caracode/pins
bash
bun add -d @caracode/pins

Then add it to astro.config.mjs. There are no options.

js
import { defineConfig } from 'astro/config';
import pins from '@caracode/pins';

export default defineConfig({
  integrations: [pins()],
});

Check it's working

Start the dev server as usual. A map-pin button appears in the Astro dev toolbar at the bottom of the page, and the terminal says it installed the Claude skill into .claude/skills/pins/.

bash
pnpm astro dev

How a pass works

  1. Open PinsClick the Pins button in the dev toolbar.
  2. Pin thingsTurn on pin mode, click an element, type a note, press ⌘ ↵. Pin mode stays on for the next one.
  3. Work the pinsIn Claude Code, in the site's folder, say "work the pins".
  4. ReviewEach changed pin moves to review with Claude's note on what it did. The panel updates by itself.
  5. Done or replyMark it done, or reply ("no, indigo") to send it back.

Pin statuses

Open

Waiting for Claude. New pins start here, and any reply you make on a review or done pin sends it back here.

Review

Claude made the change and said what it did. Your turn to look.

Done

You checked it. Only you can mark a pin done. Done pins are hidden unless you show them.

With Claude Code

The first astro dev writes a Claude Code skill into your repo, so any session in that folder knows the pin format. Just ask:

work the pins/pinscheck the pinswhat's pinnedwhat content fields did I pin?

By default Claude changes the component, so pinning one card changes every card. Say "just this one" in the note to narrow it. If a note is unclear, Claude replies with a question and leaves the pin open.

Content notes, like "image or video, optional CTA", aren't built by "work the pins". Claude skips them and lists them, so you can plan your CMS from them.

The panel

  • Push (default) narrows the page to make room, like docked devtools. Under 1280px wide it overlays on the right instead.
  • Right or Left overlay the page and tuck into a tab while you're pinning.
  • ⌘ ↵ saves (Ctrl+Enter on Windows and Linux). Esc cancels a note, then leaves pin mode.
  • Numbered markers show only while the panel is open.
  • A pin whose element is gone is marked lost rather than guessed.
  • Works with Astro view transitions: the panel follows you between pages.

What it writes

.carapin/ holds one JSON file per page: / is index.json, /blog/post/ is blog/post.json. Commit them or ignore them, whichever suits you.

.claude/skills/pins/SKILL.md is the skill. It updates itself when the package updates. Delete its marker line and it becomes yours; Pins won't overwrite it again.

Nothing else, and only while astro dev is running.

Limits

  • Astro 7 or later, dev only.
  • Source locations come from your .astro files. Elements inside React, Vue or Svelte components point at the nearest .astro element around them.
  • .md and .mdx content isn't annotated, but you can still pin it.
  • The panel shows the current page's pins only.

Shortened: real pins also carry timestamps, a selector for the exact instance, and the chain of files the element sits in. The full format is in the skill file.

Update or remove

bash
# update (the skill refreshes on the next astro dev)
pnpm up @caracode/pins

# remove: take pins() out of astro.config.mjs first
pnpm remove @caracode/pins

Delete .carapin/ and .claude/skills/pins/ as well if you don't want to keep your pins or the skill.
