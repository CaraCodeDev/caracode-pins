# M1 — Spike: element to file round trip

Status: **M1 shipped; exit verified except Rich's hover check (step 9) · next: M2** · Last updated: 2026-09-23

**State detail:** M1 was planned on the assumption that Astro adds
`data-astro-source-file` / `data-astro-source-loc` in dev. M0 found Astro 7.3.4
doesn't (its Rust compiler stubs that option). This doc keeps the spec's intent
(every pin knows its file and line) and makes supplying those locations part of
the spike. Throwaway-tolerant: the code may be rewritten in M2, but what it
proves must be written down.

Rich places a pin by clicking an element. For Claude to act on it, the pin has
to say which file and line that element came from. M1 proves the whole path
works before M2 builds the real UI on top of it: click, capture anchors, send to
the dev server, write JSON, and hear about edits made to that JSON on disk.

---

## Core framing

Three different "where"s, easy to conflate:

| Anchor | Answers | Survives | Breaks when |
|---|---|---|---|
| **Source location** (file:line:col) | Where in the code Claude should edit | Markup changes elsewhere on the page | That element's line moves (fine: Claude re-finds it by reading the file) |
| **CSS selector** | Which exact instance on the page (2nd card, not 1st) | Edits to the element's own content | Siblings added/removed, classes renamed |
| **Text snippet** | What the element looked like, for a human or Claude | Structural changes | Copy changes |

The source location is the one Claude needs most (notes/spec.md → "Anchoring",
"Component by default"). With a repeated component, every instance shares one
source location. That's the point: a pin on the second feature card means
`FeatureCard.astro` by default.

## Decisions (locked 2026-09-23)

1. **carapin supplies source locations itself, in dev only.** Astro 7.3.4's
   compiler (`@astrojs/compiler-rs` 0.4.x) marks `annotateSourceFile` as an
   unimplemented stub, and Astro 7 has no way back to the old compiler. So the
   integration adds a **dev-only** Vite transform that runs on `.astro` files
   before Astro compiles them and adds an attribute recording file, line and
   column to each plain HTML element in the template.
   - *Rejected: pin Astro 6.* Rich's real sites are on Astro 7; a tool that
     needs an old Astro is dead on arrival.
   - *Rejected: selector + text only.* It would leave Claude guessing at files,
     which is the problem carapin exists to remove.
   - *Rejected: wait for Astro to implement it.* Unknown timeline. When Astro
     ships it, carapin can read Astro's attributes and drop its own transform;
     note that in the build report, don't build for it now.
2. **The attribute is `data-pins-src`, value `<path relative to the site root>:<line>:<col>`**,
   e.g. `src/components/FeatureCard.astro:13:1`. Relative paths so pin files are
   portable between machines and readable in diffs.
3. **Only plain HTML elements in `.astro` templates get the attribute.** Not
   component tags (`<FeatureCard>`, capitalised or dotted names), not
   `<Fragment>`, `<slot>`, `<script>`, `<style>`, `<head>`-level meta/link tags,
   nothing inside frontmatter or `{expressions}` that aren't themselves markup.
   **Framework components (React, Svelte…) and `.md`/`.mdx` are out of scope for M1**; a
   click on such an element falls back to its nearest annotated ancestor.
4. **Never in production.** The transform is registered only when
   `command === 'dev'`. The M0 rule holds: `astro build` output contains no trace
   of carapin, now including no `data-pins-src`.
5. **A pin records the nearest annotated element's location, plus a source
   chain.** Clicking an element that isn't annotated (or clicking a child) uses
   the nearest ancestor with `data-pins-src`. The pin also records the distinct
   files walking up the ancestors (e.g. `FeatureCard.astro` → `pages/index.astro`),
   so Claude can see which page used the component without guessing.
6. **Spike file layout: `.carapin/<page>.json` at the site root**, where `/` →
   `index.json` and `/blog/post/` → `blog/post.json`. The spike's JSON shape is
   provisional; M2 sets the real format (notes/spec.md → "Data model"). Keep it
   pretty-printed with 2-space indent.
7. **The dev server re-reads the file before every write and holds no copy in
   memory** (notes/spec.md → "Non-functional requirements", most load-bearing).
   Even in a spike, because the edit-by-hand check depends on it.

## What's built so far (the contract)

- **Phase 1 — source locations.** `sourceLocationsPlugin(siteRoot)` (`packages/pins/src/vite-plugin.ts:18`): Vite plugin, `apply: 'serve'`, hook-level `transform.order: 'pre'` (needed: Astro's own compile plugin is also `enforce: 'pre'` and listed earlier), registered from `astro:config:setup` only when `command === 'dev'`. Calls `annotateAstroSource(code, relPath)` (`src/source-attr.ts:45`), which uses `@astrojs/compiler-rs`'s `parse()` and only *inserts* ` data-pins-src="<site-relative path>:<line>:<col>"` (1-based, UTF-16 columns) after each plain element's tag name. Skips components, Fragment, slot, script, style, html, head and everything in it, frontmatter, comments, `is:raw`; annotates markup inside `{expressions}` (e.g. `.map` output); skips files outside the site root or in `node_modules`. `<body>` is annotated, so source chains end in the layout.
- **Phase 2 — round trip.** Toolbar app (`src/toolbar/app.ts`): "Pin an element" / "Stop pinning" toggle; pin mode stays on after a click; Escape (keyup) leaves pin mode without closing the panel; closing the panel also ends it. Pin mode blocks page clicks via capture listeners on `window` (mouse + pointer down/up/click), all on one `AbortController`. Capture helpers `src/toolbar/capture.ts`: `sourceInfo` (nearest `data-pins-src` + distinct-file chain), `buildSelector` (nearest `id`, else `body > …` with `:nth-of-type` only where same-tag siblings exist), `snippet`. Messages `caracode-pins:{list,add,pins}` (`src/types.ts`). Server (`src/index.ts` `astro:server:setup`): per-file write queue; `appendPin` / `readPins` in `src/store.ts` re-read from disk every time; invalid JSON is an error sent to the panel and the file is left alone. `pageKey` (`src/pages.ts:8`): `/`→`index`, `/blog/post/`→`blog/post`, rejects `..`. `server.watcher` on `<root>/.carapin/` pushes add/change/unlink to the panel. Provisional file: `{ page, pins: [{ id, createdAt, note, source, sourceChain, selector, text, tag }] }`.
- **Tests:** vitest + happy-dom, `packages/pins/test/{source-attr,store,capture}.test.ts` (43), `pnpm --filter @caracode/pins test`.

## Watch-outs / known limitations

- **Style-only HMR is lost for `.astro` files.** Astro compares the file on disk with what it compiled (now annotated), so they never match; a `<style>` edit does a full module update instead of a CSS swap. Works, just coarser. Accepted for now.
- **Pin mode blocks mouse/pointer events only.** Keyboard activation (Enter on a focused link) still reaches the page in pin mode. Accepted for the spike; M2 decides.

- **Port 4321 is Rich's other project.** Never touch it.
- **The transform runs on every `.astro` file, including ones in `node_modules`.**
  Only annotate files inside the site's own root (not `node_modules`), and don't
  annotate the package's own files.
- **Astro 7 backgrounds `astro dev` when it detects an agent**; the playground's
  dev script uses `--ignore-lock` to stay in the foreground. Stop only processes
  you started.
- **The toolbar lives in shadow DOM.** Hover/click detection must ignore the
  toolbar itself and carapin's own overlay.
- **Where `.carapin/` goes:** the site root (the Astro project root, `playground/`
  here), not the workspace root. `playground/.carapin/` should not be git-ignored
  by this repo's `.gitignore` for the spike; M2 decides.
- **Selectors for repeated components** must include position (e.g.
  `:nth-of-type` / `:nth-child`) or they'll match all three cards.

## Open questions / decide during build

- **Parser choice for the transform** — if Astro's installed compiler exposes a
  parse API with source positions, use it; otherwise use a maintained HTML
  tokenizer and treat `{…}` expressions and frontmatter as opaque. If neither
  handles the playground's templates without breaking the page, **stop and report**:
  that reopens Decision 1 for Rich.
- **Selector strategy** — if an element or ancestor has an `id`, anchor from the
  nearest id; otherwise build a path from `body` with `:nth-of-type`. Keep it
  short enough to read.
