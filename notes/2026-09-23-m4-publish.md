# M4 — Publish and first real site

Status: **Phase 1 shipped; repo public at github.com/CaraCodeDev/caracode-pins · published as `@caracode/pins@0.1.0` · next: a real-site pass (Phase 3)** · Last updated: 2026-09-23

carapin works end to end in the playground. M4 gets it onto npm as `@caracode/pins`
and into one of Rich's real Astro sites for a real pass.

---

## Decisions (locked 2026-09-23)

1. **First published version is `0.1.0`.** Pre-1.0 says "works, format may still change".
2. **Publishing is Rich's step.** It's outward-facing and needs his npm login. Claude
   prepares everything and hands back the exact command. (Same as the Vivid CLI:
   `@caracode/vivid-cli` was published under this scope.)
3. **The README is for a developer who has never heard of carapin**: what it does in
   two sentences, install, how a pass works (pin → "work the pins" → review → done),
   the file format in brief, what it writes (`.carapin/`, `.claude/skills/pins/`), and
   the limits (Astro 7, dev only, `.astro` templates only). No marketing.
4. **Licence MIT** (already in `package.json`); add a `LICENSE` file.
5. **The package builds before packing** (`prepack`), so a publish can't ship a stale `dist/`.

## Watch-outs

- **pnpm's release-age window.** A fresh site installing Astro 7.3.4 today needs `minimumReleaseAgeExclude` for `astro@7.3.4` and `@astrojs/markdown-satteri@0.4.2`, plus `allowBuilds: { esbuild: true }`. That's Astro's install, not carapin's, and goes away as those versions age.

- **Port 4321 is Rich's other project** (a Tina site). Never touch it.
- **pnpm `workspace:*`** is rewritten on publish only by `pnpm publish`, not `npm publish`.
  The package itself has no workspace deps, so either works, but use pnpm.
